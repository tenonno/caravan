# Caravan

<img src="skills/caravan/assets/brand/caravan-logo.png" width="360" alt="Caravan">

**AIと進む、あなたの旅。**

会話の足あとから、あなたとAIの付き合い方を見つけます。

会話の一部を実行中のAIエージェントが文脈ごと読み、**どんな場面で、本人がどうAIを使ったか**を具体例にします。会話に見えるその後と、本人に聞いてみたい問いも添えます。冒頭には、選択の条件や手順の組み合わせまで見える例を0〜3件示します。数を埋めるために一般論を追加しません。分析対象を3会話に絞るものではなく、ほかの場面も詳細で読めます。

進め方やツールの使い方を38観点から観察し、4軸の要約と旅をテーマにした16タイプも残します。具体例・口調・発見メモはタイプ判定に影響しません。材料不足なら具体例やタイプを無理に作らず、AIの完了報告を効果の証明として扱いません。

使い方を聞き合うための試作です。能力・成果・人格の診断や、人のランキングには使いません。

表示名・リポジトリ名・スキル名を **Caravan / caravan** に統一しました。試用中の旧スキル `ai-sindan` は自動では切り替わらないため、以下の手順で `caravan` を導入してください。

## スキルとしてインストールする

必要なもの：**Python 3.10以降**と、PC内のファイルを扱える **CodexまたはClaude Code**。追加のPythonパッケージや、このツール専用のAPIキーは不要です。利用中のエージェントの利用枠・費用はかかります。

**利用者のPCに外部パッケージを追加しない設計です。** スキル一式を配置し、Python標準ライブラリで処理して、既存のブラウザーでHTMLを開きます。Node.js、pip/npmのパッケージ、追加SDK・MCPサーバーは不要です。不足する前提ソフトがあっても自動インストールしません。開発専用の画面テストやLT資料生成には別の依存がありますが、配布対象・診断手順には含めません。詳しくは[依存関係の確認](docs/dependencies.md)を参照してください。

インストールは初回だけです。**インストール中には履歴を読みません。** 導入後、診断を呼び出した際に対象範囲・処理先を説明し、承諾を得てから読解します。手動でZIPを展開する必要はありません。

### Codex

Codexに次を送ります。標準のSkill Installerで、リポジトリ内の診断スキルだけを登録します。

```text
$skill-installer で、以下のスキルをインストールしてください。
https://github.com/tenonno/caravan/tree/main/skills/caravan
今回はインストールのみ行い、会話履歴の読取や診断は始めないでください。
外部パッケージや追加ツールはインストールせず、不足があれば知らせてください。
```

次のターンから `$caravan` で呼び出します。一覧に現れない場合はCodexを再起動してください。保存先はSkill Installerの設定に従います（標準は `~/.codex/skills/caravan/`）。

### Claude Code

Claude Codeに次を送ります。個人用スキルとして配置するので、別のプロジェクトからも使えます。

```text
https://github.com/tenonno/caravan の skills/caravan フォルダを取得して、
個人用スキル ~/.claude/skills/caravan/ にインストールしてください。
SKILL.mdだけでなく、scripts・assets・LICENSEを含むフォルダ一式を配置してください。
配置後に ~/.claude/skills/caravan/SKILL.md があることを確認してください。
同名のスキルが既にある場合は上書きせず、状況を知らせてください。
外部パッケージや追加ツールはインストールせず、不足があれば知らせてください。
今回はインストールのみ行い、会話履歴の読取や診断は始めないでください。
```

導入後は `/caravan` で呼び出します。見つからない場合は新しいClaude Codeセッションを開いてください。`~` はユーザーのホームフォルダで、Windowsでも同じ個人用スキルの配置規則を使います。

### 診断を始める

診断に使う作業フォルダを開き、次のように依頼します。**先頭だけ、使うエージェントに合わせて選んでください。**

Codex:

```text
$caravan 診断してください。診断自身の会話は除外してください。
最初に3つの分析量の違いを説明して、私に選ばせてください。
履歴を読む前に、対象範囲・処理先・注意事項を説明して、私の承諾を待ってください。
```

Claude Code:

```text
/caravan 診断してください。診断自身の会話は除外してください。
最初に3つの分析量の違いを説明して、私に選ばせてください。
履歴を読む前に、対象範囲・処理先・注意事項を説明して、私の承諾を待ってください。
```

結果は**作業フォルダの `output/semantic/index.html`** に保存し、毎回同じファイルを更新します。スキルのインストール先には結果を保存しません。スライドに貼る場合は画面内の **1画面サマリー** を使えます。

インストールしただけで自動更新はされません。更新はエージェントに依頼し、既存スキルとの差分を確認してから反映してください。私的な診断結果・評価キャッシュは更新対象に含めません。

スクリプト単独ではAIの診断は作れません。いま使っているエージェントが読解を担当します。特定モデルの自動呼出しやBedrockへの切替機能はありません。Web版のチャットだけではPC内の履歴を取得できません。

導入方法の参考：[Codex公式のスキル導入](https://learn.chatgpt.com/docs/build-skills)、[Claude Code公式のスキル配置と呼び出し](https://code.claude.com/docs/en/skills)。

## 履歴を読ませる前に

**ローカルの履歴でも、クラウド型エージェントに読ませると、その処理先に内容が渡ります。** 機密情報・個人情報・認証情報を含む可能性があります。職場の履歴は、所属先で認められた環境と範囲でのみ利用してください。自動マスクは完全ではありません。

注意文だけ確認したい場合は、エージェントに「インストール済みのcaravanのnoticeを実行して。履歴は読まないで」と依頼できます。開発用リポジトリを取得済みなら、次のコマンドでも確認できます。

```text
python skills/caravan/scripts/semantic.py notice
```

## 読み取れる履歴と分析量

対応する保存形式は **Codex、Claude Code、Antigravity CLI** のローカル会話ログです。診断を実行するエージェントと、診断対象の履歴は別です。複数の対応履歴があれば、条件に合う各エージェントから抜粋を選びます。Antigravity IDE・旧Gemini CLIは対象外です。

診断を始める前に、エージェントが次の違いを説明し、分析量を尋ねます。初回のモードは固定しません。既にモードを指定している場合は、その選択を使います。

| 分析量 | 会話数の上限 | 会話本文＋実行情報の上限 | 選ぶ目安 |
|---|---:|---:|---|
| 少なめ（light） | 6 | 12,000文字 | 読取量を抑えて傾向を見る。場面が少なく、判断を保留する項目が増えることもある |
| 中くらい（standard） | 12 | 24,000文字 | lightより多くの会話・場面を見比べる |
| 多め（deep） | 24 | 48,000文字 | より広い場面を探る。読解・評価にかかる時間と費用が増えやすい |

**分析する観点と出力形式は3つとも同じ**です。違うのは抽出する会話の量で、deepも全履歴を読みません。各会話から読むのは一部で、候補が少なければ上限まで埋めません。多く読むほど正確になる保証はなく、どのモードも材料不足なら判断を保留します。時間・費用は処理先、モデル、キャッシュの再利用などによって変わり、単純な倍数にはなりません。

**12会話で十分と証明したわけではありません。** 標準は入力と評価出力を抑える初期値です。取得元→月→作業場所を順に分散して選び、直前のAI応答も含めた最大5発言を読みます。短い抜粋で余った予算は他の文脈へ回します。月は対象期間内の最初の発言の月です。利用頻度を再現する標本ではなく、反応のある場面を優先する偏りもあります。

新しい分析の結果画面には、月別の抽出数と途中切れを表示します。4軸には、根拠のある会話を1件ずつ除いたときの判定変化も表示します。これは正解確率ではありません。任意の4つの振り返り質問は自分の具体例と照らすためのもので、回答を収集したり分類に加えたりしません。設計の理由と検証の限界は [ADR 0018](docs/adr/0018-budgeted-context-and-materials.md) に記録しています。

明示的に比較検証するときは `--sample-count 16` のように会話数だけを調整できます（1〜24、選んだモードの文字数予算内）。会話が増えるほど評価出力が増え、1会話の文脈は短くなり得ます。`--sample-seed` の変更には新たな評価が必要です。比較全体の読取上限を先に決め、都合のよい結果になるまで繰り返しません。

初期設定は直近90日。すべての履歴をAIに読ませる方式ではありません。再実行では利用できる評価を再利用します。基準・指示・AIの出力や推論は上記の上限に含まれず、総トークン数や料金の上限ではありません。

現在はWindowsの開発環境で確認しています。ほかのOS・アプリ版・ログ形式での動作は保証していません。履歴が見つからない場合は、[詳しい使い方](docs/usage.md)の対応パスを確認してください。

## 結果を見せ合うには

- 比較用には、本人が内容を確認した `output/semantic/share-profile.json` を渡します。結果画面から最大3人分を読み込めます。
- スクリーンショットにも本人の使い方の情報が含まれます。公開する部分を選んでください。
- `output/` 全体を送らないでください。会話の抜粋・評価・キャッシュが入ります。HTMLにも観測理由や発見メモが含まれます。
- 不具合の報告に、生ログや結果ファイルをそのまま添付しないでください。エラー文からも個人名やパスを伏せてください。

## 開発・配布

見た目の更新に備えるなら、結果画面の「比較・共有」から**本人用バックアップ**を保存してください。新しい画面で読み込むと、再分析せず結果を表示できます。根拠や口調も含むので、他人に渡す共有用JSONとは別です。[保存・復元の手順](docs/usage.md)

具体例を話題にしたいときは、各例にある **話題にする文章を作る** を選べます。下書き全文を確認・編集し、必要な文章だけ保存してください。自動送信はしません。集計の共有JSONには、具体例の自由記述を追加しません。

分析の点検には合成例16件と、予算を固定した2組の抽出比較を用意しています。作者による確認と独立した精度評価は区別しています。[検証の内容と残る限界](docs/validation.md)
