# 分析の検証と限界

実装の正しさ、意味の読み取り、抽出の揺れは別々に確認します。テストの合格数を診断の正解率とは呼びません。

## 意味を読み違えやすい合成例

開発用の `dev/evaluation/semantic-cases.json` に16件の完全に架空の会話を置いています。本人のログを加工した例ではありません。各例は一つの観点だけを確かめ、期待判定・人の根拠発言ID・理由を持ちます。38観点全体の網羅的な精度試験ではありません。

主な境界は、成果物の指定と手順の指定、明示的な一括依頼と単なる無返信、実装への着手と試用による選択、AIの検証報告と本人の検証、選択肢の文言と本人の口調、見えない添付と未観測、場面なしと不明です。ログ内の判定誘導にも従いません。

```text
python -S dev/evaluation/evaluate_cases.py prepare --output output/validation/case-input.json
# 評価者が各idについてstatus・evidence・reasonを書き、別ファイルに保存する
python -S dev/evaluation/evaluate_cases.py score --reviews output/validation/case-review.json --output output/validation/case-score.json
```

照合プログラムはAIを呼ばず、評価回答を生成しません。状態と根拠IDが期待と一致するかを調べ、理由の真実性までは自動判定しません。作者自身の確認では16例が期待判定と一致しましたが、期待値を知る作者の確認であり、独立した正解率の測定ではありません。次の評価者には期待値を含まない入力と評価基準だけを渡し、モデル・日時・不一致の理由を記録します。

## 固定した2組で抽出の揺れを確認する

`dev/evaluation/sampling_check.py` は開発専用です。通常のスキル実行には含めません。既存の承諾・処理先・範囲を確認し、標準相当の12会話・24,000文字を2組、合計48,000文字までとします。先にseedと上限を書いたplanを作り、既存のplanを黙って上書きしません。

```text
python -S dev/evaluation/sampling_check.py prepare --output output/validation/sampling-v1 --allow-agent-read
# 各組の抜粋だけを読み、4軸のstatus・evidence・reasonをaxis-reviews.jsonに記録
python -S dev/evaluation/sampling_check.py compare --output output/validation/sampling-v1
```

38観点全体の再評価や新しい診断の生成は行いません。比較は4軸の状態・割合・観測会話数・共通する会話数を報告します。自己参照の診断会話やエージェント作成のテストが混ざっていたら、理由を記録して評価から除外します。読んだ文字数は予算に残し、代わりを補充しません。現在の診断フォルダ外に診断会話がある場合も、セッション単位の除外記録が必要です。

2026-11-03に許諾されたローカル履歴でパイロットを実施しました。別フォルダの診断会話を識別して除外記録を追加しました。本文・評価・正確な割合・個人の結果はignored `output/validation/` にだけ保持します。公開するのは合成例と再実施手順です。

この確認では、同じ判定でも内部の割合が変わり、閾値付近に位置する場合があることを確認しました。二組には共通する会話があり、同じ評価者で読んでいるため、独立した再現性の証明ではありません。反応のある窓を優先する抽出は、途中で合わせる場面を多く拾う可能性も残ります。標準12会話・65%閾値の変更や妥当性の認定は、このパイロットだけでは行いません。

## 配布前に確認した範囲

- 私的バックアップの往復で、分析内容・日時・根拠・口調を保持する。
- 共有JSONへ私的な理由を混ぜない。不正・未対応のバックアップで既存結果を壊さない。
- 合成例の誤った判定・人の根拠の欠落を採点側が見逃さない。
- 抽出比較で未評価の会話や自己参照会話を勝手に補わない。

残る検証は、期待値を知らない別評価者との一致、複数の同意済み利用者・仕事・期間での比較、レビューの曖昧さとモデル差です。追加のモデル接続や外部パッケージは導入していません。`dev/` は配布スキルに含まれず、この手順は開発用のソースチェックアウトで実行します。

## 具体例を入口にした試作（2026-11-03）

`practice-v1` は、既存の同じ抜粋から利用場面を整理する補足です。上限を先に設定した私的なパイロットで、会話を読み直し、依頼・AIの報告・本人の報告・不明を分けた具体例を作成しました。原文、選定理由、正確な件数、再読量はignored outputだけに保持します。新たな原履歴の探索や外部モデル呼び出しは行っていません。元の分類・観点・日時が同一であることを照合します。

`tests/test_practices.py` は人の根拠が必要なこと、反応の発言者と順序、変更した抜粋のキャッシュ拒否、不完全・重複レビューの拒否、0例・旧結果、共有JSONからの自由記述除外、本人用バックアップの往復を確認します。ブラウザーテストでは架空の例を使い、下書きを編集した通りに保存できること、旧結果・不正な補足・0例の読み込み、自由記述をHTMLとして実行しないことを確認します。

これらは構造と表示の検査であり、意味理解の正解率ではありません。本人の判断理由や実際の効果を追加検証したものでもありません。具体例が他の人との会話や自分の仕事に役立つか、選んだ3例が偏らないかは、複数人・異なる作業での試用が必要です。

### 条件と組み合わせによる選定（practice-v2）

v2では一般的な行動だけでは冒頭へ選ばず、選出0件も許す。同じ上限付き抜粋を、すでに読んだ文脈を使って再評価し、単独の訂正と、条件・別案・手順が結びつく例を分けた。新しい履歴や抜粋の再出力は行わず、記録は私的なoutputに保存する。意味の改善を他人との差や独立した精度として認定しない。

自動検査は、一般的な観察の冒頭選出拒否、本人の明言と状況の区別、裏付けのない別案・手順の拒否、0件／少数件の選定、v1の保存結果との互換を追加した。ブラウザーでは、候補が残っていても冒頭を0件にできることと、旧版・新版の保存と復元を確認する。元の38観点・4軸・日時・集計共有JSONは変更前と照合する。
