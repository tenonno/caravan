# 0027: 詳細JSONは現在の分類だけを保存する

- 状態: Accepted
- 記録日・決定日: 2026-11-04
- 記録種別: 新規決定
- 実装状況: 実装済み
- 関連ADR: [0008](0008-travel-names-and-art.md)、[0019](0019-private-result-backup.md)

## 背景

詳細JSONに旧タイプ名と現在の分類が混在し、結果を誤読する余地があった。旧データを保存対象から除く要望を受けた。

## 決定と理由

portrait-v1がある結果のエクスポートでは、トップレベルの旧分類の判定、候補、一覧、材料充足情報を除く。4軸側のタイプ名と説明は現在の旅人カタログに合わせる。コード、根拠、具体例、口調、発見メモ、件数、診断日時は変更しない。ブラウザーとCLIに適用し、古いバックアップを読み込んだ後の再保存も同様に扱う。

0008・0019の元データをそのまま保存する方針を、詳細JSONの旧分類と表示名に限って変更する。元のreport.jsonや評価キャッシュは書き換えない。旧形式も引き続き受け付け、4軸未評価の結果では唯一の判定である旧分類を残す。新しい分類を推測しない。

## 比較対象

旧分類の単なる改名では二つの分類の混在が解消しない。すべての旧結果から削除すると4軸未評価の結果を復元できない。

## 影響・トレードオフ

再保存したJSONは旧ファイルとの完全一致ではなくなる。旧分類なしでも両HTMLを復元できるようにする。既存v1の読み込みに変更はなく、共有JSONの許可項目も増やさない。

## 再検討する条件

保存形式の版変更や、4軸以外の分類方式を導入する場合。
