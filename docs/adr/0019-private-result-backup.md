# 0019: 本人用バックアップを共有用プロフィールと分ける

- 状態: Accepted

- 実装状況: 実装済み

## 背景

配布後の表示更新に備え、再分析せず本人の結果を持ち運びたい。共有用JSONは情報を意図的に減らしているため、根拠・口調・発見メモを復元できない。

## 決定と理由

`caravan-private-backup-v1` を設け、保存済みreportと任意の実行集計を一つのJSONに保持する。診断日時・分類・理由を保持し、原文抜粋・レビューキャッシュ・画像・スクリプトを含めない。本人用と共有用は別の操作・説明にし、共有形式の許可項目は増やさない。

ブラウザーではローカルファイルから画面内だけに復元する。永続保存・自動送信・元ファイルの上書きはせず、元の開発者ページへのリンクを隠して誤参照を防ぐ。現在の組み込み画像を用い、データ中のHTMLを実行しない。8 MiB・深さ・版・観点IDを検査し、描画に失敗すれば前の表示に戻す。

Pythonでは新しいテンプレートで結果・詳細・共有JSONを再生成する。別の一時場所で検証・描画してから固定ファイルに反映し、既存結果の置換には明示的な `--replace` を要する。旧結果を本人用バックアップに保存してから置換し、取り込み元にない実行集計を前の結果から混ぜない。マニフェストやキャッシュは復元せず、再分析には元の材料が必要。

## 比較対象

- 共有JSONだけを使う：省略情報を復元できない。
- 全outputを固める：原文・キャッシュまで持ち出しやすくなる。
- インポートしたHTMLを実行する：コードとデータの境界がなくなる。

## 影響・トレードオフ

二種類の保存形式がある。本人用には仕事の情報を含む理由があり、共有に不向き。ブラウザーだけの復元は閉じると消えるため、継続して閲覧するなら再読込またはスキルでの再生成が必要。未知の形式は互換性を推測せず拒否する。古い結果にない新観点は未評価のまま表示する。

## 再検討する条件

データ形式・共有範囲・保存先を変える、別端末間の自動同期や再評価の再開を求められた場合。
