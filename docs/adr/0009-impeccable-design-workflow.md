# 0009: Impeccableで既存画面のデザインを継続的に整える

- 状態: Accepted
- 記録日・決定日: 2026-11-03
- 記録種別: 新規決定
- 実装状況: 実装済み（導入・初回polish。実ブラウザーでの目視確認は未完了）
- 関連ADR: [0007 固定レポート](0007-stable-standalone-reports.md)、[0008 旅の愛称と画像](0008-travel-names-and-art.md)

## 背景

イラスト導入後の画面を、統一した判断基準で整える必要がある。ユーザーからImpeccableの導入とデザイン調整の依頼があった。

## 決定と理由

公式Impeccableを開発用スキルとして導入し、既存画面の調整にはpolishを使う。旅のイラスト、生成り・青緑・オレンジの配色、診断と表示の分離を維持し、情報の優先順位、読みやすさ、操作状態、画像の比率を点検する。

導入版は4.8.0、公式リポジトリのコミット `9fadc41729c38fd47d7ae622b501558653f9d2e9` に固定した。スキルは開発者の環境へ置き、生成HTMLの実行依存にはしない。今回は自動フックを追加せず、contextの指示に従って手動の検査を一度実行する方式を採用した。

検査結果は修正候補として扱い、実装の意味を確認してから直す。自動検査・操作ロジックのテスト・実画面の目視確認は区別し、未実施の確認を完了扱いにしない。

## 比較対象

- 検査ルールだけに合わせた全面改装：承認済みのイラストや配色まで置き換えてしまう。
- HTMLにデザインツールを組み込む：持ち出せる単独HTMLという要件に不要な依存が増える。
- 自動フックの導入：現段階では手動適用で目的を満たすため採用しない。比較は設計上の整理で、これらを実験したという意味ではない。

## 影響・トレードオフ

再利用できる点検手順を得る一方、スキルの別途インストールが必要になる。検査には静的テンプレートの動的画像や既存の配色を誤検出する場合がある。例外は具体的な要素と理由を記録し、全体の警告を無効化しない。

初回は補助文字・操作領域・見出しの優先順位を調整し、表示切替とタイプ選択時に説明へ移動する処理を追加した。画像、観測値、分類基準は変更しない。

## 再検討する条件

スキル更新時、配色や情報構造を全面変更するとき、自動フックや外部連携が必要になったとき。実画面で破綻が見つかった場合は検査の成功にかかわらず修正する。
