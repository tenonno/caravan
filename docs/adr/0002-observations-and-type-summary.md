# 0002: 優劣を測らず、多観点の観察と4軸の要約を分ける

- 状態: Accepted
- 記録日: 2026-11-03
- 決定日: 不明（事後記録）
- 記録種別: 事後記録
- 実装状況: 実装済み

## 背景

目的は、友人・他職種の仲間・先輩がAIをどう使うかを知り、話を聞く入口を作ること。覚えやすい16タイプだけでは、豊富な使い方や未知の工夫を捉えきれない。ユーザーは指標を増やしつつ、良し悪しの測定にしないことを明示した。

## 決定と理由

詳細な観察と見出しの分類を分ける。現在は38観点を保持し、同じ抜粋をAIが別途読み、根拠と関連観点を添えて「相談の入口」「進め方の裁量」「合わせるタイミング」「選択の手がかり」の4軸に要約する。4軸の組み合わせが16タイプの入口になる。38観点の件数を機械的に二分して4軸へ変換しない。

中間・併用・材料不足を許し、未観測を反対側とみなさない。タイプは今回の場面の傾向であり、能力・成熟度・固定した性格・信頼の強さではない。閾値や軸の独立性は未検証と扱う。

口調と自由な発見メモは分類と独立させる。発見は既存観点の具体例と枠外の候補を区別し、人の根拠と本人への問いを添える。0件も正常。技法の世界的新規性や効果を認定せず、自動的に正式指標へ追加しない。

## 比較対象

- 4軸だけを測る：細かな使い分けや未知の工夫を失う。
- 全観点を総合点にする：利用頻度や複雑さを優劣と誤解させやすい。
- 全員を必ず一つのタイプにする：乏しい根拠から断定してしまう。
- 初期の18観点によるプロトタイプ照合を主見出しに使い続ける：現在は4軸の根拠付き要約を優先し、旧方式は互換用途に残す。

## 影響・トレードオフ

分かりやすい見出しと詳細を両立する一方、評価出力と読解コストが増える。38観点と4軸は別の評価日時・キャッシュを持つ。旧結果を未評価の新方式へ自動変換せず、異なる方式の共有データを直接比較しない。

## 再検討する条件

実利用でタイプの説明が誤解を生む、軸が重複する、再現性が低い、新たな観察項目を正式採用する必要が出た場合。定義を変える際は評価基準の版と再評価の要否も検討する。

## 根拠・関連実装

会話中の「他職種の使い方を知る」「観点を増やす」「優劣を測らない」「未知のテクニックと口調も見たい」という要望。
