# 0030: 公開先と公開用ブランチを開発リポジトリで管理する

- 状態: Accepted
- 記録日・決定日: 2026-11-04
- 記録種別: 新規決定
- 実装状況: 実装済み
- 関連ADR: [0011](0011-public-distribution.md)、[0029](0029-private-presentations-outside-repository.md)

## 背景

別の作業コピーだけにremoteがあると、開発場所から公開経路や反映状況を確認できない。

## 決定と理由

開発リポジトリに公開先のoriginを設定する。public/mainはorigin/mainを追跡し、同じGit管理下のoutput/publish-main worktreeで公開用の変更を準備する。明示一覧から選んだ内容だけを既存の公開履歴へ追加する。開発履歴を公開履歴へ結合しない。

push.default=nothingで引数なしのpushを無効化し、公開を依頼されたときだけpublic/main:mainを明示して送る。別リポジトリの作業コピーによる従来の公開経路は廃止する。

## 比較対象

- 別コピーを使い続ける：公開先が開発場所から見えず、同期が分かりにくい。
- 開発履歴を直接pushする：公開一覧にない過去の内容まで公開するおそれがある。
- 公開履歴を置き換える：既存の履歴を保持した通常の追加で更新できるため不要。

## 影響・トレードオフ

remoteと公開状況を同じリポジトリで確認できる。公開用ブランチには明示一覧の同期が必要であり、開発ブランチのmergeは行わない。公開前の内容確認とユーザーによる公開指示は引き続き必要。

## 再検討する条件

開発ブランチ自体を公開できるように配布範囲を変更する場合、または公開工程を自動化する場合。
