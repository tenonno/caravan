# 0012: 個人用スキルの導入と診断の作業場所を分ける

- 関連ADR: [0004](0004-consent-and-private-data.md)、[0007](0007-stable-standalone-reports.md)、[0011](0011-public-distribution.md)

## 背景

リポジトリを取得して手順書を読ませる案内では、エージェントが継続して名前で呼び出せるスキル登録にならない。個人用スキルの導入先と、診断を実行する作業フォルダも異なる。

## 決定と理由

標準の案内を、CodexではSkill Installerによる導入、Claude Codeでは個人用スキルディレクトリへの一式配置とする。前者は `$ai-sindan`、後者は `/ai-sindan` で呼び出す。両者で同じSKILL.md・スクリプト・アセットを用いる。フォルダ単体の配布でもライセンスを保持する。

リソースはSKILL.mdの所在から解決し、私的な出力は診断の作業フォルダの `output/semantic/` に置く。Git管理下では出力の無視設定と追跡されていないことを抽出前に確認する。固定HTMLの名前は変えない。インストール時は履歴を読まず、診断時の説明・承諾を維持する。

0011の公開ソースの選別と新しいGit履歴は維持し、利用者の入口を直接実行からインストールへ変更する。プラグイン化・自動更新は今回導入しない。

## 比較対象

- リポジトリを毎回指定して実行：スキルとしての再利用に向かない。
- 診断結果をスキル内へ保存：スキルの更新や共有に私的情報が混ざり得る。
- エージェントごとに診断本体を複製：指標と承諾手順が分岐する。

## 影響・トレードオフ

初回の導入が必要だが、以後は名前で呼び出せる。実行場所が変わるため絶対パスでスクリプトを呼ぶ。配置変更の自動テストは両エージェントの実セッションによる診断を保証するものではない。

## 再検討する条件

公式のスキル登録方式が変わる、プラグイン配布や自動更新を導入する場合。
