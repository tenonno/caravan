# 0001: ADRをリポジトリで運用する

- 状態: Accepted
- 記録日・決定日: 2026-11-03
- 記録種別: 新規決定
- 実装状況: 実装済み（文書運用）

## 背景

会話を通じて指標・分類・読取方式・出力が変化し、「なぜ今の構成か」をREADMEやコードだけから復元しにくくなった。ユーザーからADR運用の開始と、この会話の重要な決定の記録を依頼された。

## 決定と理由

`docs/adr/` に番号付きMarkdownと一覧・テンプレートを置く。[運用手順](README.md)に従い、設計の理由を実装と同じGitで管理する。過去分は会話と実装で確認できる判断だけを事後記録し、不明な決定日を補わない。今後は関連する設計変更と一緒に更新する。

## 比較対象

- 会話だけに残す：後から探しにくく、別のエージェントへ引き継ぎにくい。
- READMEに判断経緯も集約する：利用手順が長くなり、現在の仕様と過去の理由が混ざる。
- 全変更にADRを要求する：軽微な修正まで記録の負担を増やすため採用しない。

## 影響・トレードオフ

保守する文書が増える。一方、意味のある決定に対象を絞り、新たなツールや承認フローを導入しない。変更された判断は後続ADRで置換し、採用時の理由を残す。ADRに私的な診断データを入れない。

## 再検討する条件

共同開発やレビュー体制が変わり、状態管理・責任者・文書検索に現行方式では不足が出た場合。
