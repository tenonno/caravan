# 0008: 旅の愛称と共通の画像制作ルールを表示層で管理する

- 状態: Accepted
- 記録日・決定日: 2026-11-03
- 記録種別: 事後記録（本会話と同日の実装）
- 実装状況: 実装済み
- 関連ADR: [0002 観察と要約](0002-observations-and-type-summary.md)、[0007 固定レポート](0007-stable-standalone-reports.md)

## 背景

「プロデューサー」のような職業名は仕事の役割を連想させ、他職種同士で使い方を話す入口として硬い。ユーザーは旅のテーマを選び、16枚の絵柄を統一した画像と再利用できる制作スキルを求めた。

## 決定と理由

安定した4文字コードに旅の愛称・短い説明・画像を対応させる。愛称は覚えやすさを担い、説明と4軸が使い方の意味を担う。名前や画像は判定の入力にしない。過去の保存済み診断はコードから現在の愛称を表示し、元の評価日時・判定・共有JSONを上書きしない。旧分類へは適用せず、中間・材料不足に単独の絵を当てはめない。

共通の旅人とAIの相棒を、生成り・青緑・オレンジの絵本風で描く。全タイプに同程度の親しみと対等な関係を持たせ、道具や場面で違いを表す。画像内に文字を入れず、HTMLで名前と代替テキストを付ける。

組み込み画像生成を用い、共通の基準画像を参照して一枚ずつ制作する。制作スキルと全プロンプト、元PNG・配信用JPEGをGitで保持し、HTMLには軽量版を埋め込む。個人の履歴や診断理由を画像生成へ送らない。

## 比較対象

- 職業名を続ける：職種・能力の分類と誤解されやすい。
- 名前を変えるため再診断する：表示上の変更と評価が結び付く。
- 毎回異なるプロンプトだけで描く：絵柄が揃わず、修正を引き継ぎにくい。
- 外部URLだけで画像を参照する：単独HTMLとして持ち出せない。

## 影響・トレードオフ

比喩だけで診断の意味は伝わらないため、具体的な説明を添える。生成画像の再生成には揺らぎがあり、参照画像・プロンプトだけでなく目視確認も必要になる。元画像でリポジトリ容量が増えるが、再利用・品質保持を優先する。配信用の縮小・圧縮は元画像とは分ける。

## 再検討する条件

名前に序列や誤解が生まれる、テーマを変更する、4軸の意味やコードを変える、別の出力サイズ・制作手段を必要とする場合。通常の一枚の修正だけで新ADRは作らない。

## 根拠・関連実装

仕事らしすぎない名前の要望、旅の提案の選択、統一した16枚と画像制作スキルの作成依頼。
