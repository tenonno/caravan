# 0004: 読取の承諾・処理先の説明・共有項目の制限を維持する

- 状態: Accepted
- 記録日: 2026-11-03

- 記録種別: 事後記録

## 背景

履歴には仕事の機密情報や個人情報が含まれ得る。ローカルファイルを読むことと、ローカルモデルだけで処理することは同じではない。ユーザーは配布時に注意を出し、勝手にAIへ読ませない運用を求めた。

## 決定と理由

抽出・読取前に、対象範囲・処理先・組織の規則・自動マスクの限界を説明し、明示的な承諾を得る。CLIフラグはその承諾の後に使う。同じ範囲と処理先で有効な承諾がある場合は重ねて求めず、変更時は改めて確認する。

Bedrock等は選び得る環境の例であり、安全性を名称だけで保証しない。現実装は接続先の切替を行わない。特定モデル・リージョン・価格をこの決定に含めない。

履歴・抜粋・評価キャッシュ・生成レポートは無視対象の `output/` に保持する。コード・定義・文書・テスト・汎用画像をローカルGitで管理し、依頼なく公開・pushしない。動作確認のためエージェントが作成した会話は本人の行動から除外する。

本人が選んで共有するJSONは許可項目だけで構成する。原文・日時・氏名・プロジェクト情報・正確な件数・口調・自由な発見文・実行監査を含めない。比較はブラウザー内で処理し、自動送信しない。

## 比較対象

- PCへのアクセス許可だけで分析を始める：クラウドへの処理経路が伝わらない。
- 自動マスクだけに依存する：機密性を完全には判定できない。
- HTMLやレビュー全体を共有形式にする：自由記述から仕事や本人の情報が伝わり得る。

## 影響・トレードオフ

初回に説明が必要で、共有できる情報は限定される。共有JSONも完全な匿名性を保証するものではない。CLIは承諾の真正性やレビューの安全性を単独では保証できず、実行エージェントの手順も必要になる。

## 再検討する条件

新しい処理先・自動送信・共有項目・保存先・クラウド保存を追加する場合。実装と説明、既存の承諾範囲を併せて見直す。
