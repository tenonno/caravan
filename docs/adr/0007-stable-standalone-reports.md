# 0007: 固定HTML・独立した詳細画面・診断と表示の分離

- 状態: Accepted
- 記録日: 2026-11-03

- 記録種別: 事後記録

## 背景

更新ごとに別名のHTMLを作ると、アプリ内ブラウザーで古いリンクを開きやすくなった。また、指標が増えるにつれて結果ページが長くなり、何を見ればよいか分かりにくくなった。開発者向けの判断基準は、将来別にエクスポートできる形が求められた。

## 決定と理由

標準出力を `output/semantic/index.html`、開発者向け詳細を `output/semantic/developer.html` に固定し、上書きする。キャッシュ回避のための日時付きコピーを作らない。

保存済み `report.json` から表示だけを再生成できるようにする。表示変更では原本の診断データ・分析日時を更新せず、HTML更新日時を別に示す。

両HTMLは個別に使える単独ファイルとし、外部フォント・画像配信・JavaScriptライブラリーに依存しない。結果は「結果」「詳しい観察」「比較・共有」「16タイプ」を切り替え、根拠の折りたたみと観点の検索を用意する。詳細画面には定義・判断条件・集計を載せ、会話原文や個別の観測理由を含めない。

## 比較対象

- 更新ごとに新しいファイルを配る：どれが最新か分からなくなる。
- 見た目の変更のたびに再診断する：不要な読取費用が発生し、日時や結果まで変わる。
- 全説明を一画面に常時展開する：主要な結果が埋もれる。
- ホストされたWebアプリを必須にする：現在のローカル出力・個別持ち出しの目的には不要。

## 影響・トレードオフ

ファイルを開くだけで使える一方、ブラウザーの古い表示には再読み込みが必要な場合がある。画像の埋め込みはHTMLの容量を増やす。開発者画面の「現在の実装」と、保存済み診断の評価時点を混同しない表示が必要になる。

## 再検討する条件

配布・公開方式を決める、履歴比較を製品機能として設計する、単独HTMLの容量や操作性が支障になる場合。

## 根拠・関連実装

古いHTMLを開いてしまう問題、固定リンク、開発者向け詳細、長いページの整理についての要望。
