## 背景

導入後の依頼例が初回lightに固定されていた。利用者が読取量と負担の違いを理解して選べる入口にしたい。

## 決定と理由

スキルはlight・standard・deepの会話数と文字数の上限、場面の広さ、時間・費用への影響を説明する。指定がない場合は本人が選ぶまで抽出を始めない。既に明示したモードや前回の設定を再利用する指示は尊重し、重ねて選択を求めない。

3つとも観察項目・評価規則・出力形式は同じ。量を増やしても精度やタイプ確定を保証せず、deepでも全履歴は読まない。文字数は総トークンや料金の上限ではなく、費用が単純な倍数になるとも説明しない。

処理先・範囲の説明とモード選択をまとめて提示する。選択のみを読取の承諾とみなさず、説明後の明示的承諾を維持する。同じ範囲・処理先で有効な承諾は再取得しない。CLIの既定値は互換性のため変更せず、スキルは選択したモードを明示して実行する。

## 比較対象

- 初回light固定：読取量は抑えられるが本人の選択を反映しない。
- CLI既定値への依存：選択なしでstandardになる。
- モードを診断の品質ランクとして表示：評価規則が同じことや不確実性を誤解させる。

## 影響・トレードオフ

未指定の場合は開始時に選択が必要。選択済みの場合は追加の往復を増やさない。スキル更新前のインストールには新しい案内は反映されない。

## 再検討する条件

サンプリング予算、評価項目、課金経路を変更する場合。

## 根拠・関連実装

初回lightの固定を外し、違いを説明したうえで利用者が選べるようにしたいという要望。
