# 0005: 複数エージェントの履歴を抽出枠に含める

- 状態: Accepted
- 記録日: 2026-11-03
- 決定日: 不明（事後記録）
- 記録種別: 事後記録
- 実装状況: 実装済み

## 背景

複数のエージェントを使う人について、一つの製品の履歴だけから使い方を説明すると偏りが生じる。「読むAI」と「読まれる履歴の製品」も混同しやすい。

## 決定と理由

読解担当のAIと履歴の取得元を分離する。現行の対応元はCodex・Claude Code・Antigravity CLI。対象条件を満たす取得元に一枠ずつ交代で割り当て、各取得元の中では月・作業場所を分散させる。候補が尽きた枠は他へ回す。

対象条件を満たす全取得元から最低一会話を含める。小さな予算でそれができないときは、黙って省かず停止する。候補数・選択数と対象外の理由を結果へ出す。条件を満たす履歴がない製品まで「診断済み」としない。

取得元ごとの既知の形式を明示し、未知の入力を推測しない。Antigravity CLIの会話JSONL対応を、IDE・旧Gemini CLI・バイナリ会話DBの対応と同一視しない。診断のために別CLIを起動して会話を作らない。

## 比較対象

- 全履歴から件数比例で抽出する：多用する製品だけで枠が埋まる。
- 製品ごとに上限なしで分析を足す：全体の読取予算を維持できない。
- 全製品を同じログ形式として読む：役割や自動通知を取り違える。

## 影響・トレードオフ

取得元の取りこぼしを抑える代わりに、実際の使用割合を再現する標本ではなくなる。ログの保存状態や形式変更に左右され、非対応・除外・読取不可の明示が必要になる。

## 再検討する条件

取得元を増やす、最小モードの枠を超える数の製品に対応する、利用割合そのものを推定する目的へ変わる場合。
