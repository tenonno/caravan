# 0024: 結果の要点と詳しい観察を分ける

- 状態: Accepted
- 記録日・決定日: 2026-11-03
- 記録種別: 新規決定
- 実装状況: 実装済み
- 関連ADR: [0007](0007-stable-standalone-reports.md)、[0023](0023-overview-before-practices.md)の追加例の配置のみ置換

## 背景

結果の下部で、具体例の概要と全文、問い、依頼例、追加例、口調が続き、情報の役割と読む順序が分かりにくくなっていた。利用者から内部参照番号の削除と、長い下部の整理を依頼された。

## 決定と理由

冒頭の旅人と4軸は維持する。直後に選出済みの具体例を一度だけ示し、概要の重複を目次に置き換える。各例を「会話で起きたこと」と「振り返る・試してみる」に分け、PCでは横に並べ、狭い幅では同じ順序で積む。問いと仮の依頼例は観察の事実と区別する。

追加例・口調・従来の発見メモを既存の「詳しい観察」にまとめる。追加例への件数付き導線を結果に残す。具体例の全文を折りたたまず、選出なし・未評価・旧結果にも入口と説明を用意する。観点の検索は詳しい観察の先頭で使える状態を保つ。

会話IDと発言参照番号は利用者向けHTMLの表示から除く。根拠の説明と保存済みデータの参照情報は保持する。開発者ページへ個別の内容を移さず、0007の境界を維持する。分類・評価・選出・分析日時・保存共有形式は変更しない。

## 比較対象

- 全文をたたむ：以前の「たたみすぎ」という指摘を再発させるため採用しない。
- 全追加例を結果に並べ続ける：役割分けだけでは長さを十分に減らせない。
- 説明文を短く書き換える：今回の表示整理で観察の解釈まで変えない。

## 影響・トレードオフ

結果の要点を追いやすくなる。追加例と口調には画面切り替えが必要になるが、同じ固定HTML内に保持される。内部番号を見て照合したい場合は保存データを使う。

## 再検討する条件

追加例への入口が見つからない場合、または具体例の数が増えて詳しい観察内でも探しにくくなる場合。
