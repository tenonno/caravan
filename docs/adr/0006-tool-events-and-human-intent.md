# 0006: ツールの実行記録と本人の意図を分ける

## 背景

モデルの使い分け、スキル、MCP、サブエージェントなども観察したい。しかし、利用可能な設定、AIが自発的に行った操作、本人が選んだ使い方は異なる。

## 決定と理由

会話から読む本人の意図と、構造化された実行記録を別に扱う。12のツール運用観点に優劣のない選択肢を設け、人の発言の根拠を必須にする。実行イベントは補助根拠にできるが、それだけで意図・採用・有効性を推定しない。

設定・要求・応答・成功を同一視しない。実行監査は独立した対象範囲と日時で表示し、会話診断や共有JSONへ混ぜない。イベント数・文字数に上限を置き、非対応・省略を表示する。

スキル・MCPの名称はハッシュ化し、モデルIDは限定して保持する。引数本文・出力本文・思考内容・接続先・認証情報を監査出力へ入れない。既知の接頭辞を使う独自モデル名など、完全には識別できない限界も残す。

## 比較対象

- インストールや設定から利用を推定する：実利用や本人の選択を証明しない。
- 呼出し数を熟練度の点数にする：目的である使い方の違いから外れる。
- 全ツール本文をAIへ送る：予算と機密情報の境界を広げる。

## 影響・トレードオフ

控えめな観測となり、包装された呼出しや非対応形式は不明のままになる。現行の監査はCodex・Claude Codeの対応イベントに限定され、Antigravity CLIの会話対応とは範囲が異なる。0件は未利用の証明ではない。

## 再検討する条件

新しい実行形式を扱う、本人が選んだことを示す根拠を追加できる、監査の対象範囲や保持項目を変える場合。
