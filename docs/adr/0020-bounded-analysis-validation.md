# 0020: 合成例の意味確認と固定した抽出比較を分ける

- 状態: Accepted
- 記録日・決定日: 2026-11-03
- 記録種別: 新規決定
- 実装状況: 実装済み
- 関連ADR: [0003](0003-bounded-semantic-review.md)、[0004](0004-consent-and-private-data.md)、[0018](0018-budgeted-context-and-materials.md)

## 背景

実装の単体テストだけではAIの誤読や抽出の揺れを確認できない。配布前に点検可能な例と、合計予算を固定した比較を求められた。

## 決定と理由

架空の短い会話16例に、対象観点・期待判定・根拠・理由を付ける。評価者の回答を別ファイルで受け、状態と根拠参照を照合する。自動判定でAI評価を捏造せず、採点プログラムはレビューを生成しない。現在の作者自身による確認は独立した精度評価とは呼ばない。

実履歴のパイロットは標準モード相当の2組、合計48,000文字を先に上限とし、固定seedで抽出する。通常の診断を上書きせず、4軸だけを根拠付きで評価する。自己参照の診断会話・エージェントが作ったテストを見つけたら評価から除外するが、読んだ予算には含め、都合のよい結果を得るため補充・再抽出しない。

判定の一致だけでなく、観測割合・判定可能な会話数・共有する会話数・途中切れ・除外を記録する。二組に同じ会話が多ければ独立した再現性とは扱わない。少人数・同じ評価者の結果から閾値・標準会話数を最適と認定しない。

## 比較対象

- 単体テスト合格を精度の証明とする：意味の誤読を測れない。
- 合成例の自己採点を正解率とする：作者と評価者が独立していない。
- 望むタイプになるまで追加抽出する：予算と比較条件が崩れる。
- 追加のモデルAPIを使う：新しい処理経路と依存を増やすため、この検証には採用しない。

## 影響・トレードオフ

開発専用の検証手順が増える。パイロットの本文・レビュー・正確な結果はignored outputに保管し、公開コードには合成例と手順だけを残す。意味の理由自体の正しさや、他人・別モデルに対する一般性は今後の独立レビューが必要。

## 再検討する条件

独立した評価者・複数の同意済み利用者・異なるモデルを使った比較を実施できる場合。
