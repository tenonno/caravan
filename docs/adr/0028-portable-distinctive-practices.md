# 0028: プロジェクトを知らなくても伝わる、特徴的な選択の組み合わせ

- 状態: Accepted
- 記録日・決定日: 2026-11-04
- 記録種別: 新規決定
- 実装状況: 実装済み
- 関連ADR: [0022](0022-specific-choices-without-quota.md)の選定確認を補強。[0024](0024-result-reading-structure.md)の配置と共有境界は維持。

## 背景

利用者が知りたいのは、その人の特徴が表れるAIの使い方である。プロジェクト内の作業記録は背景を知らない読者に伝わりにくく、一般的な助言へ抽象化すると選択の特徴が失われる。条件や複数手順があるだけでも、通常の訂正や作業一覧を選出し得る。

## 決定と理由

選出時に二つの意味確認を加える。固有の用語を役割に置き換えても、AIへの任せ方と選択の条件が伝わるか。さらに、一般的な助言に還元されず、残すもの・見送る案・切り替える時点・任せる範囲の具体的な組み合わせが残るか。両方を満たした理由を私的レビューのreasonに記す。条件・別案は引き続き根拠を必要とし、一般的な人の行動を仮定した比較はしない。

既存のtitleとhuman_actionで組み合わせを説明し、conditionで必要最小限の背景、alternativeとstepsで観察の裏付けを示す。表示では使い方を背景より先に読む。新しい自由記述項目や採点は設けない。特徴的とは観察された選択の具体性を指し、他者より珍しい、優れている、普段もそうする、他の仕事でも効果があるという認定ではない。0〜3例の可変件数を維持。

定義にselection_revisionを加え、定義全体を含む既存キャッシュキーを更新する。構造はpractice-v2のまま。旧保存結果は表示・復元可能で、render時に新基準で選び直した扱いにしない。

利用者が既存結果の説明改善を求めた場合は、保存済み観察に基づく文章調整を可能とする。私的な変更前バックアップを残し、選出・根拠参照・条件の確度・分析日時・分類と共有JSONは維持する。元の履歴を再評価したと説明しない。選出や意味を変える場合は、承諾済みの上限付き抜粋の完全なレビューを必要とする。

## 比較対象

- 専門用語だけを言い換える：作業一覧のままで、本人の選び方が見えない。
- 一般的なコツを見出しにする：他の仕事でも通じるが、特徴を知る目的を失う。
- 他者との希少性を採点する：比較対象のデータがなく、根拠がない。
- 保存結果を自動で再選出する：旧分析を新基準で確認済みと誤認させる。

## 影響・トレードオフ

プロジェクトを知らない読者にも選択を説明しやすくなる。一方、一般的な行動だけの抜粋では掲載件数が減る。確認は分析者の意味判断を伴い、構造テストでは妥当性を保証できない。読取範囲や共有対象を広げず、追加依存も導入しない。

## 再検討する条件

本人に選択の特徴として受け取られない、条件を消した一般論になる、専門背景が依然として必要、または根拠のない動機や他者比較が混入する場合。
