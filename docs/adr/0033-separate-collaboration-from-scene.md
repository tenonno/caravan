# 0033: AIとの進め方を、根拠となる作業場面と分けて生成する

- 状態: Accepted
- 記録日・決定日: 2026-11-04
- 記録種別: 新規決定
- 実装状況: 実装済み
- 関連ADR: [0028](0028-portable-distinctive-practices.md)の生成項目と確認手順を置換。[0022](0022-specific-choices-without-quota.md)の根拠・件数・非評価の原則は継続。

## 背景

作業の具体的な説明と、他の分野の人にも伝わるAIの使い方を同じ項目で生成していた。そのため、抽象化を指示しても、専門用語を言い換えた作業記録に戻りやすかった。成果物だけを推敲しても次回の生成に反映されないため、生成の構造から変更する。

## 決定と理由

新規レビューをpractice-v3にする。具体的な場面と選択を根拠付きで整理した後、別項目のcollaborationで「AIとの進め方」と「人が決めた条件・任せた範囲」を生成する。各説明は場面の整理に使った本人の発言を参照する。抽象化に必要な根拠がなければnullにできる。

生成後は場面の説明を隠して読み、別の分野の人にも任せ方と選択の条件が伝わるかを確認する。その後、具体的な場面と照合し、意図や効果を補っていないか確かめる。確認結果は私的レビューのportabilityとreasonに残す。一般論しか残らない例、作業の背景がないと理解できない例、根拠が足りない例は冒頭に載せない。掲載は引き続き0〜3例で、件数を埋めない。

表示では新しい説明を先に置き、その下に根拠となった場面と振り返りを示す。共有用の文章を利用者が開いた場合も、両方を区別して含める。集計共有JSONには含めない。

定義全体を含むキャッシュキーにより、旧レビューの自動再利用を防ぐ。旧v1/v2の保存結果は元の意味のまま表示・復元でき、render時に新項目を補完しない。新形式での生成には同意済みの同じ抽出範囲についてレビューをそろえる。分類・読取範囲・元の分析日時を変えず、使い方の整理には独立した更新日時を持たせる。

## 比較対象

- 成果物だけを書き換える：次の生成時に同じ問題が起こり得る。
- 指示文だけを追加する：作業記録とAIとの進め方を同じ項目で書く構造が残る。
- 用語の置換で抽象化する：選択の条件を消したり、根拠のない一般論に変えたりするおそれがある。
- 意味を自動採点する：構造と発言参照の検査では、抽象度の適切さを保証できない。

これらは判断のために整理した比較対象であり、効果を比較実験した結果ではない。

## 影響・トレードオフ

説明と根拠の役割が明確になる一方、生成と確認に追加の文章が必要になる。確認結果は分析者の判断であり、他者に対する希少性、優劣、別の場面での有効性を認定しない。新しい外部サービスや配布依存は追加しない。

## 再検討する条件

別項目でも作業記録の繰り返しになる、一般的な助言だけになる、または根拠にない意図・効果を補う例が続く場合。
