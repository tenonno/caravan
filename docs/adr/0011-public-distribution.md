# 0011: 明示したファイルだけを新しい履歴で公開する

- 状態: Accepted
- 記録日: 2026-11-03
- 決定日: 2026-11-03
- 記録種別: 新規決定
- 実装状況: 配布物の生成を実装。GitHubへのアップロードは別工程
- 関連ADR: [0004](0004-consent-and-private-data.md)、[0007](0007-stable-standalone-reports.md)

## 背景

少人数に試してもらいたいが、リポジトリのアクセス権を個別に付与したくない。開発用のGitには配布に不要な資料や過去の環境固有の記述が含まれる。

## 決定と理由

MITライセンスの公開GitHubリポジトリを配布先とする。初回公開は明示一覧から作ったZIPを新しい作業コピーへ展開し、新しいGit履歴を作る。既存の開発履歴をpushしない。コード・文書・テスト・タイプ画像を配布し、診断スキルのアセットは省かない。

利用者はリポジトリURLを自分のエージェントに渡し、取得とSKILL.mdの実行を依頼する。手動のZIP展開は必須にしない。履歴を読む前の説明と承諾は維持する。配布の公開性は履歴の読取・公開の承諾を意味しない。診断結果や履歴を収集するサービスは追加しない。

## 比較対象

- 開発リポジトリをそのまま公開：過去の資料まで公開するため採用しない。
- 非公開リポジトリへの招待：アクセス権を設定せず渡す目的に合わない。
- フォルダの一括圧縮：未追跡の履歴などが混ざり得るため採用しない。

## 影響・トレードオフ

ファイル追加時には配布一覧の更新が必要。明示一覧は既存ファイル内への機密情報混入を検出しないため、本文の確認も必要。公開用と開発用の履歴が分かれ、初回以後は差分の反映を管理する。

## 再検討する条件

外部コントリビューターによる共同開発、更新自動化、追加の配布形式や処理先を導入する場合。

## 根拠・関連実装

アクセス権設定なしで少人数に配布したいという要望と、MITライセンスでの公開の選択。
