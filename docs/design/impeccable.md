# Impeccableを使うデザイン調整

採用理由は [ADR 0009](../adr/0009-impeccable-design-workflow.md)。この文書は開発手順で、診断基準ではありません。

## 導入

公式配布元は [pbakaus/impeccable](https://github.com/pbakaus/impeccable)。初回導入は4.8.0、コミット `9fadc41729c38fd47d7ae622b501558653f9d2e9`、ソースは `.agents/skills/impeccable`。Codexのskill-installerを使って、ユーザーの `$CODEX_HOME/skills/impeccable`（標準では `~/.codex/skills/impeccable`）へ導入しました。インストーラーへ渡す引数は以下です。

```text
--repo pbakaus/impeccable --ref 9fadc41729c38fd47d7ae622b501558653f9d2e9 --path .agents/skills/impeccable
```

スキル本体をこのリポジトリに複製しません。更新時は導入版・参照コミットと変更内容を確認してください。生成HTMLにはImpeccableやその通信処理を含めません。

## 画面を整えるとき

1. インストール済みの `SKILL.md` と該当する参照手順を読む。小規模な仕上げには `polish`、同じ世界観を大胆に表現する依頼には `bolder` を使う。「変化が欲しい」という要望を微調整だけで済ませない。正式なデザインシステムが未作成の場合も、既存テンプレートとADR 0008の世界観を基準にする。
2. スキルの `scripts/impeccable.cmd context --target skills/ai-sindan/assets/semantic-report.html` をセッションに一度実行し、案内された手順を適用する。今回のCLI実行では `DO_NOT_TRACK=1` を設定した。
3. 元の診断を再実行せず、既存 `report.json` を固定の2画面へrenderする。日時・画像の縦横比・材料不足と旧結果の表示を守る。
4. 自動検査がない場合はcontextの指示に従い、編集後に手動detectを一度実行する。警告は実装と照合し、実際の問題を直す。検査のために私的レポートを公開しない。
5. Pythonテストと両画面のNode操作テストを実行する。利用可能なブラウザーで広い画面・狭い画面、文字拡大、キーボード操作も確認する。アクセス制限で実施できない検証は明記する。

手動検査の対象は以下の2テンプレートです。検査ログは個人のパスを含むため、保存する場合は無視対象の `output/` に置きます。

```text
detect --json skills/ai-sindan/assets/semantic-report.html skills/ai-sindan/assets/developer-report.html
```

## 初回検査の扱い（2026-11-03）

5件の警告を確認。詳細画面の11px文字に対する2件は13pxに修正しました。次の3件は要素単位で理由を確認した例外です。ルール全体の抑制はしていません。

| 検出 | 対象と理由 |
|---|---|
| broken-image | 結果画面の `#journey-hero` は初期状態でhidden。画像が存在する場合だけJavaScriptが埋め込み画像のsrcを設定して表示する。材料不足・旧結果では非表示を維持し、操作テストで両方を確認する。 |
| cramped-padding | 詳細画面の `.table-scroll` は表のスクロール境界。セル内には12pxの余白があり、囲み全体へ重ねて余白を足さない。 |
| cream-palette | 詳細画面の生成り背景は、ユーザーが選んだ旅のイラストとADR 0008に合わせた意図的な配色。 |

初回のローカルHTMLはブラウザー操作のURL制限で目視確認できていません。静的検査と操作ロジックのテストは、実ブラウザーのレイアウト・フォーカス表示を保証しません。

## 表現を強めた調整（2026-11-03）

初回のpolishでは変化が小さいとのフィードバックを受け、結果画面全体にbolderを適用しました。PCでは青緑の左ナビゲーションと、タイプ名・大きなイラストの見開き構成。4軸は背景をまとめて読み取り位置を揃え、図鑑は選択中の説明と絵の一覧を並べます。狭い画面では上部ナビゲーション・縦積みに切り替えます。表示内容、4画面の機能、診断・共有データは維持します。

この調整の手動検査は結果テンプレートに一度実行し、前述の動的な `#journey-hero` の警告のみでした。コード確認・操作テストと、実画面の確認は引き続き別扱いです。

## Caravanのロゴ適用（2026-11-03）

既存の旅の世界観を維持するpolishとして、結果・発表用サマリー・詳細画面に軽量な透過ロゴを配置した。比率を維持し、サイドバーでは生成りの下地で文字のコントラストを確保する。[制作と容量の記録](caravan.md)も参照。

61件のPythonテストと両画面のNode操作テストに成功。手動detectは既に記録済みのbroken-image・cramped-padding・cream-paletteの3件のみで、新しい警告はない。ロゴ画像自体は目視確認し、HTML内の埋め込みと寸法も検証した。実ブラウザーのページ確認は既存のローカルURLアクセス制限により未実施で、レイアウト検証済みとは扱わない。
